form_nav 项目背景与框架变更说明
项目：~/catkin_ws/src/form_nav，ROS Noetic + PX4 + Gazebo，多无人机编队导航。技术栈：全局层 A*（+轻量取锯齿后处理），局部层 MPC（CasADi + IPOPT，一阶速度动力学 + 偏航），障碍物避碰用 KD-tree 查询最近上一轮预测轨迹每个预测位置的最近的三个障碍点位置，编队通信拓扑为有向无环图（无双向通信），各机互发预测轨迹用于编队防碰。
原框架
- 全局层：集中式——只规划一条"虚拟中心"轨迹，各机用"轨迹点 + 自身编队偏移"作为自己的参考；
- 局部层：MPC 逐点跟踪全局轨迹——预测时域内每一步都对应全局轨迹上该时刻的参考点，高权重跟踪位置（running cost 只有位置误差，参考速度仅用于终端惩罚）；
- 设计来源：参考了一篇编队跟踪/包含控制（formation tracking-containment）论文，其任务是"严格跟踪移动目标"，所以参考轨迹是外部给定、带时间戳的。
修改后框架
- 全局层：改为分布式——每架无人机用自己的起点状态和自己的编队分配目标点，独立调用 A* 规划自己的全局轨迹；编队偏移只用于分配终点，以及作为规划/控制的软约束。全局轨迹的作用从"逐点参考"降级为"提供全局方向、避免局部最优"；
- 局部层：MPC 从逐点跟踪改为在全局轨迹上滚动选取子目标（沿路径取一个前瞻量，跟踪该子目标），保留障碍避碰、编队防碰、控制增量惩罚、上一轮解热启动；
- 优先级避让：利用无双向通信的有向无环拓扑，"接收者避让发布者的预测轨迹"，天然形成一致的优先级（leader 最高，逐级向下），避免相互避让造成的振荡；
- 队形：不再全程保持刚性编队，只要求终点恢复编队；由于起点终点按编队位置分配，开阔段中间路线自然保持大致队形，绕障时允许暂时松散；
- RL 自适应前瞻量/自适应调整mpc代价函数权重（还未完成）：子目标前瞻量的大小对局部轨迹质量影响明显且无固定规律，计划用 RL 学习输出最优前瞻量（自适应调节）。
为什么修改
1. 逐点跟踪对全局路径质量过度敏感：kinoA* 轨迹是分段常加速度，节点处加速度跳变、绕障转弯曲率集中、终点 shot 段可能产生钩状路径，MPC 逐点高权重跟踪导致绕障时振荡；
2. 偏移后的集中式轨迹对跟随者不优甚至不可行：轨迹按虚拟中心规划，各机偏移后路径可能穿障碍、速度剖面与自身起点状态不匹配；
3. 导航任务本质是"到达静态目标"，时间自由：强制按全局轨迹时间戳跟踪是过度约束，滚动子目标（路径跟随）才匹配任务；
4. 全程刚性编队应用价值低：改为巡航段松散 + 终点恢复队形；
5. 无双向通信拓扑下，发布者优先级机制自然成立且避免对称避让振荡。
